# Руководство для участников проекта

## Структура проекта

Основа учебного проекта Хекслета — приложение на React и TypeScript со сборкой через Vite. В [сценарии записи на звонок](README.md#сценарий-записи-на-звонок) описано, как владелец и гость будут пользоваться календарём.

Файл `index.html` загружает `src/main.tsx`, который монтирует корневой компонент из `src/App.tsx`. Размещайте глобальные стили в `src/index.css`, а стили компонента App — в `src/App.css`. Импортируйте изображения для сборки из `src/assets/`. Файлы, которым нужен постоянный URL, помещайте в `public/` и указывайте путь от корня сайта, например `/icons.svg`.

## Команды для разработки

Выполняйте команды из корня репозитория.

| Команда | Назначение |
| --- | --- |
| `npm ci` | Устанавливает версии зависимостей, зафиксированные в `package-lock.json`. |
| `npm run dev` | Запускает сервер разработки Vite с горячей перезагрузкой. |
| `npm run lint` | Проверяет код с помощью Oxlint, в том числе соблюдение правил хуков React. |
| `npm run build` | Проверяет код компилятором TypeScript и создаёт продакшен-сборку в `dist/`. |
| `npm run preview` | Запускает локальный сервер для просмотра последней продакшен-сборки. |

## Стиль кода

В TSX-файлах используйте отступ в два пробела, одинарные кавычки в импортах и двойные в атрибутах JSX. Опускайте точки с запятой в конце инструкций. Для компонентов и их файлов используйте PascalCase (`App.tsx`), для переменных и обработчиков — camelCase. Выбирайте расширение `.tsx` для модулей с JSX и `.ts` для остальных модулей TypeScript.

## Тестирование

Запускайте линтер и сборку локально. В проекте пока нет инструмента для локального запуска тестов, соглашения об их именовании и минимального порога покрытия. Хекслет запускает внешнюю проверку при каждом push. Сохраняйте сгенерированный файл `.github/workflows/hexlet-check.yml` без изменений и не переименовывайте репозиторий.

При изменении логики бронирования проверяйте границы интервалов. Запись на 09:45–10:00 должна блокировать пересекающиеся интервалы для всех типов встреч. Свободный интервал с 10:00 должен оставаться доступным. При одновременных запросах на пересекающиеся интервалы должна подтверждаться только одна запись.

## Коммиты и пул-реквесты

Пишите короткие заголовки коммитов в повелительном наклонении по примеру `Add README.md`. В описании пул-реквеста укажите, какое поведение изменилось и как вы его проверили. Если есть связанная задача, добавьте ссылку. Приложите снимок экрана, если он поможет оценить изменения интерфейса.
